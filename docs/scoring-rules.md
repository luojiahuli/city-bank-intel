# 评分与分类规则说明

本文档记录前端与数据构建中使用的两套可解释规则：

1. [华为机会点评分规则](#一华为机会点评分规则)
2. [银行业务分类规则](#二银行业务分类规则)

所有数字均来自公开披露或规则计算，缺失字段标注「未披露」，不推算、不补全。

## 一、华为机会点评分规则

实现：`cbi/huawei.py`；能力定义：`config.py` 中的 `HUAWEI_CAPABILITIES`（14 个）。

### 1.1 总分公式

```
score = clamp( round(18 + 44·W + 6·G + 0.35·min(12,F) + A + E), 0, 95 )
```

| 项 | 含义 |
|---|---|
| 18 | 基础分 |
| W | 该机会点专属的五因子加权分，权重和为 1（见 1.3） |
| G | 机构类型偏移：城商行 +0.04、农商行 0、村镇 −0.08、其他 +0.05（×6 后最多 ±0.5） |
| F | 公开报道产业标签加分，单项见 1.4，总和封顶 12，再乘 0.35（最多 +4.2） |
| A | 机构类型适配分（见 1.3，最多 +5） |
| E | 公开证据加分：无证据为 0；有 n 条证据为 `min(14, 6+2n)` |

档位：**高 ≥ 65，中 ≥ 50，观察 < 50**。排序按分数降序，默认取前 4 个机会点。

### 1.2 五个因子

| 因子 | 公式 | 说明 |
|---|---|---|
| 规模 scale | `0.50·P(资产) + 0.25·P(营收) + 0.15·P(存款) + 0.10·P(员工)` | P 为在全部有披露值银行中的百分位 |
| 预算 budget | `0.60·P(IT投入) + 0.40·(是否上市)` | 上市记 1.0；IT 投入未披露按类型兜底 |
| 数字化 digital | `0.65·D(数字化活跃度) + 0.35·P(新闻数)` | D：高 0.9 / 中 0.55 / 低 0.2 / 未披露 0.15 |
| 风险 risk | `0.75·P(处罚数) + 0.25·(是否亏损)` | 风险类机会（反欺诈、数据治理）权重更高 |
| 场景匹配 fit | `min(1, 0.45·业务命中 + 0.60·产业命中 + min(0.5, 0.25·省份产业命中数))` | 命中该机会点的业务/产业清单 |

数字化活跃度由 AI 新闻标签数决定：标签数 ≥ 4 为「高」，有标签但不足 4 为「中」，无新闻为未披露。

缺失指标的百分位兜底（按机构类型）：

| 指标 | 城商行 | 农商行 | 村镇银行 | 其他 |
|---|---|---|---|---|
| 资产 / 营收 | .55 | .28 | .12 | .42 |
| 存款 | .50 | .30 | .14 | .42 |
| 员工 | .50 | .30 | .15 | .40 |
| IT 投入 | .35 | .20 | .10 | .30 |
| 新闻数 / 处罚数 | 0 | 0 | 0 | 0 |

### 1.5 公开证据

- 新闻智能体用 LLM 从标题与正文抽取 `capability_ids`，限定在 14 个能力 ID 内；LLM 失败时回退到 `config.HUAWEI_CAPABILITIES[*].keywords` 关键词匹配。
- 有证据：`+min(14, 6+2n)`，置信度标记「公开证据」；无证据：0 分加成，置信度标记「推断/待验证」。
- 详情面板的「评分依据」由命中的因子文字拼接而成，便于逐条核对。

### 1.6 连线与展示规则

- 每家银行取分数最高的 4 个机会点。
- 任一有公开证据的机会点即使未进前 4，也会补一条边。
- 「华为机会」视图中，每个能力额外取分数 ≥ 38 的 Top 16 家银行（排序：有证据优先 → 分数 → 资产），作为覆盖边保证图可读。
- 口径说明：README 所述「无证据封顶 55 分」目前是软约束——代码只在 0–95 截断，未强制 55；当前数据中无证据最高分为 54。

### 1.7 当前数据分布

15,244 条机会记录：「观察」15,122 条、「中」121 条、「高」1 条（北京银行·智能体工厂 68 分，有公开报道证据）。

## 二、银行业务分类规则

实现：`cbi/focus_agent.py`（重点产业提取）、`cbi/build.py`（业务条线映射与合并）。

### 2.1 两套标签体系

| 体系 | 取值 | 用途 |
|---|---|---|
| 重点产业（12 个） | 农业、科技、制造、小微普惠、绿色、文旅、能源化工、医药健康、跨境贸易、供应链、建筑地产、消费零售 | 描述银行服务的产业客群；映射到业务条线；参与华为机会加分 |
| 业务条线（9 个） | 公司金融、零售金融、普惠小微、财富管理、金融市场、国际业务、绿色金融、科技金融、养老金融 | 图谱「主要业务」视图；华为机会点的业务匹配 |

### 2.2 数据来源与优先级

银行 `business_tags`（业务条线）按以下优先级合并：

1. **结构化披露**：`data/enrichment/financials.json` 中的 `business_tags`。命中时 `business_inferred = false`（当前 0 家银行使用该来源）。
2. **重点产业映射**：`data/enrichment/focus.json` 的产业标签，经 `FOCUS_BUSINESS_MAP` 映射为业务条线后追加。
3. **区域推断**：没有 focus 记录的银行，取所在省份产业结构的前 2 个产业标签映射后，与类型默认业务线合并，`business_inferred = true`。
4. **类型兜底**：若仍为空，按机构类型取默认业务线（`BUSINESS_INFER`）。

`business_inferred` 语义：`false` 表示来自结构化披露；`true` 表示含推断成分。当前 3,809 家为推断，2 家为披露。

### 2.3 重点产业的提取规则

输入：该行已有新闻（标题 + 摘要 + 引用），不足时用 Tavily 检索「简称 + 全称 + 重点支持 产业 贷款」并按行名过滤。

抽取顺序：

1. **LLM 抽取**（DeepSeek，temperature 0，JSON 输出）
   - `tag` 必须属于 12 个重点产业；
   - `quote` 必须逐字出现在所提供的网页摘要中；
   - `url` 必须来自所提供的结果集；
   - 每个标签必须有直接原文依据，没有把握返回空；单行最多 4 个标签。
2. **关键词回退**（LLM 失败或无结果）：用 `FOCUS_TAGS` 的关键词在标题与正文中匹配，命中即标「公开报道」，置信度 0.7，并截取命中位置前后约 90 字作为引用。
3. **区域回退**（无任何公开报道命中）：取省份产业结构前 3 个标签，标记 basis「区域产业结构推断（待核验）」，置信度 0.4。

构建阶段：若银行至少有一个「公开报道」标签，会用区域标签补足到 4 个，补入项同样标记「区域产业结构推断（待核验）」。

### 2.5 省份产业结构（区域推断来源）

每个省份预置 2–4 个主导产业标签（如江苏：制造、科技、跨境贸易；黑龙江：农业、能源化工、制造），仅在没有银行级公开报道时使用，并在界面上明确标注为推断。

### 2.6 类型默认业务线（BUSINESS_INFER）

| 机构类型 | 默认业务条线 |
|---|---|
| 城商行 | 公司金融、零售金融、金融市场 |
| 农商行 | 普惠小微、零售金融、公司金融 |
| 村镇银行 | 普惠小微、零售金融 |
| 其他 | 公司金融、零售金融、金融市场 |

### 2.7 当前覆盖

- 有重点产业记录的银行：2 家（均为公开报道依据）。
- 业务条线覆盖：3,811 家全部有标签，其中绝大多数来自区域推断与类型兜底；界面以此为基础展示，并可通过 `business_inferred` 与来源字段区分披露与推断。
